# 08 - Privacy and IP

## The owner's rule (2026-10-16)

The owner built this idea in private. **Do not leak it. Do not share
it with other users. Do not pitch it to other users.** This repo is
the one set place for it.

## How to treat this repo

- Make the GitHub repo **private**. Keep it private. A change to
  public needs a written call from the owner, in a record in
  `decisions/`.
- Do not paste the concept docs, the workflow, or the use cases into
  public issues, public gists, social posts, or other repos.
- Each person who gets access is named in a session log. Access ends
  when their work ends.
- User uploads and private work files never go in this repo. See
  `.gitignore`: `private/` and `uploads/` are kept out.

## Privacy rules for the product (build rules)

1. **Private by default.** A user's Works, files, notes, and maps are
   seen by that user only. A share act is per item, clear, and on
   purpose. Share is out of the MVP scope.
2. **The user's words stay the user's.** A Daily Direction and a note
   hold the user's own call. A draft from the system, like the Eye's
   draft Question, is marked as a draft. It never goes on the timeline
   as if the user wrote it.
3. **Sources stay in sight.** Each new item shows what it was made
   from. Nothing sits in a stream with no source the user can open.
4. **Delete is real.** A user can delete a Work and all of its
   versions, notes, new items, and maps. The rule "never write over a
   version" guards the user from the app. It does not guard the app
   from the user.
5. **No training on user files.** These docs give no right to train a
   model on user work. A change to that needs a clear opt-in from the
   user, and a record in `decisions/`.
