# 03 - Use Cases

Three main use cases. They are all mine. Each one runs the same loop.
See `02`. Only three things change from case to case: how intake
splits the file, what the Daily Direction asks, and which Eye view
draws the work.

New use cases use `../templates/use-case-template.md`.

---

## Case A - YouTube and podcast content

**My goal:** take source work I like and turn it into my own content.
Make it better day by day.

1. **Hold (Hand):** I upload a video script, a podcast transcript, or
   audio notes. The Hand splits the transcript into parts: intro,
   claim, case, story, close. It makes the Work.
2. **Direct (Brain), each day:** I open the Daily Direction on that Work.
   - *Takeaway:* the one idea from the episode that stuck with me.
   - *Tweak:* one change. "Open with the story, not the claim."
     Or "Add my own case before the takeaway."
   - *Question:* the Eye drafts it, or I write my own.
   - I use it as **Revise** and get script v2. Or I use it as
     **Derive** and get title picks, a short script, show notes, or a
     quote card. Each new item links back to the transcript part it
     came from.
3. **See (Eye):** a mind map of my episode's claims, built from the
   script and my notes. A claim with no case is **Thin**. A takeaway
   that never got into my script is an **Orphan**.
4. **Return:** flags set my next day's Question. I run the loop till
   each main claim has a case or a story. That is my test for "rich
   and good to watch" in this case. I mark **Shipped** when the video
   goes up. I keep the timeline.

## Case B - CFA study

**My goal:** turn thick source files into facts I can recall and use.

1. **Hold:** I upload a chapter file, class notes, or slides. The
   Hand splits the file by section and topic.
2. **Direct, each day:**
   - *Takeaway:* one idea said in my own words. I do not copy the book.
   - *Tweak:* one act. "Redo the worked case with the book shut."
     Or "Move duration before convexity in my notes."
   - I use it as **Derive** and get flash cards or test questions from
     one section. Or I use it as **Revise** and mark up my notes once
     I see my test score.
3. **See:** a concept map of the topic. Rules and ideas are nodes.
   Links show what builds on what. A topic read once and never tested
   is **Thin**. A flash card with no node in the map is an **Orphan**.
4. **Return:** Thin topics set my next day's Question. "Can I state
   this rule with the book shut?" A topic leaves my daily loop when
   its branch holds notes, test work, and one fix. A read alone does
   not count.

## Case C - A piece of art

**My goal:** build a piece in many versions and keep the full path.

1. **Hold:** I shoot a photo of the sketch or the work in progress. I
   add source paintings or images to the same Work. Versions stack on
   one timeline.
2. **Direct, each day:**
   - *Takeaway:* what the piece is about, today, in one line.
   - *Tweak:* one change. Layout, color, or one part. Not all three.
   - I use it as **Revise** and the next version photo joins the
     stack, with my note as its caption. Or I use it as **Derive**
     and get a color study, a crop test, or a list of details to take
     from a source image.
3. **See:** a layout view. The current version sits next to its
   sources and the board my notes built. A source I saved and never
   used is an **Orphan**. A part named in my notes but in no version
   is **Thin**.
4. **Return:** I work the flag the next day. I mark **Shipped** at
   the last version. The stack is the record of how I made the piece.

---

## What the three cases show me

- The loop works for all media. The file type changes the Eye view.
  It changes nothing else.
- "Rich" is a test I can check. Each case uses the same three flags:
  Thin, Orphan, Conflict.
- The daily gain comes from the cap: one tweak. It does not come from
  more features.
