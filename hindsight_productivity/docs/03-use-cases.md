# 03 — Use Cases

Three founding use cases. Each follows the same loop
(`02-workspace-workflow.md`); only the intake split, the Daily Direction
prompts, and the Eye view change. New use cases use
`../templates/use-case-template.md`.

---

## Use case A — YouTube / podcast content for self-enhancement

**Goal:** turn source material you admire into your own, better content,
refined daily.

1. **Hold (Hand):** upload a video script, podcast transcript, or episode
   audio notes. Hand splits the transcript into segments (intro, claim,
   example, story, close) and creates the Work.
2. **Direct (Brain), daily:** open today's Daily Direction on that Work.
   - *Takeaway:* the one idea from the episode that stuck with you.
   - *Tweak:* one direction — e.g. "open with the story, not the claim",
     "add my own example before the takeaway".
   - *Question:* drafted from the Eye (see below) or your own.
   - Apply as **Revise** → your script v2, or **Derive** → title options,
     a short-form script, show notes, or a quote card, each linked to the
     transcript segment it came from.
3. **See (Eye):** mind map of *your* episode's argument, built from the
   script + all your notes. Flags: a claim with no example = **Thin**;
   a takeaway you wrote that never made it into the script = **Orphan**.
4. **Return:** flags become tomorrow's Question. Repeat until the map shows
   every main claim carrying an example or a story — the working definition
   of "rich / interesting enough" for this use case. Mark **Shipped** when
   the video is posted; keep the timeline.

## Use case B — Studying for the CFA exams

**Goal:** turn dense source material into understanding you can retrieve.

1. **Hold:** upload a chapter PDF, class notes, or a set of slides. Hand
   splits by section/topic.
2. **Direct, daily:**
   - *Takeaway:* one concept restated in your own words (not copied).
   - *Tweak:* one action — e.g. "redo the worked example without looking",
     "move duration before convexity in my notes".
   - Apply as **Derive** → flashcards or practice questions built from a
     section, or **Revise** → your notes annotated/corrected after practice.
3. **See:** concept map of the topic area — formulas and concepts as nodes,
   connections where one builds on another. Flags: a topic studied once and
   never practised = **Thin**; a formula in your flashcards with no node in
   the map = **Orphan**.
4. **Return:** thin topics draft tomorrow's Question ("Can I derive this
   without the book?"). A topic leaves the daily loop when its branch
   carries notes, practice, and a correction — not when it has been read.

## Use case C — Creating an artwork

**Goal:** develop a piece through versions without losing the thread.

1. **Hold:** photograph the sketch/work in progress; add reference paintings
   or images to the same Work. Versions live as a stack on one timeline.
2. **Direct, daily:**
   - *Takeaway:* what the piece is actually about, today, in one line.
   - *Tweak:* one change only — composition, colour, one element — not all
     three.
   - Apply as **Revise** → the next version photo joins the stack with the
     note as its caption, or **Derive** → a palette study, a crop test, a
     list of reference details to borrow.
3. **See:** composition view — the current version beside its references
   and the moodboard the notes have built. Flags: a reference you saved
   but never used = **Orphan**; an element named in notes but absent in
   every version = **Thin**.
4. **Return:** work the flag tomorrow. Mark **Shipped** at the final
   version; the stack is the record of how the piece was made.

---

## What the three cases prove about the design

- The loop is medium-agnostic: file type changes the Eye view, nothing else.
- "Interesting / rich enough" is made checkable, per case, through the same
  three Eye flags (Thin / Orphan / Conflict).
- Daily value comes from the constraint (one tweak), not from more features.
